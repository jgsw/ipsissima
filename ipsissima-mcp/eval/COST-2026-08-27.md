# What a reconstruction costs, measured on seven runs

*27 August 2026. Seven reconstructions of six papers, all through the same instructions, six of
them at `effort: max` and one pair differing only in effort. The question was the project owner's:
why did Darwin — a 266-word passage — cost nearly as much as Wilson, which is forty times longer?*

**Because almost all of it is fixed, and the part that is not tracks the map rather than the paper.**

---

## The measurements

| run | source | map | tokens | tool calls | tokens per map byte |
|---|---|---|---|---|---|
| Darwin | **266 w** | 13,222 b | 160,365 | 41 | 12.13 |
| Carroll | 1,400 w | 18,361 b | 180,889 | 37 | 9.85 |
| Miller | **10,751 w** | 45,239 b | 203,252 | 44 | 4.49 |
| Tooming | 8,895 w | 51,576 b | 207,950 | 37 | 4.03 |
| Wilson | 10,622 w | 81,683 b | 238,274 | 42 | 2.92 |
| Prescott-Couch | 8,658 w | 89,336 b | 248,637 | 45 | 2.78 |

**Forty times the source, 1.27 times the tokens.** Darwin against Miller settles the owner's
question on its own.

What the tokens actually track:

| against | correlation |
|---|---|
| **map bytes produced** | **r = +0.989** |
| source words read | r = +0.804 |
| tool calls | r = +0.505 |

The source correlation is real but borrowed: a longer paper usually yields a longer map, and it is
the map that costs. Miller is the case that separates them — the longest source in the corpus and
a middling map, sitting exactly where its map size predicts and nowhere near where its word count
would.

Least squares over the six max-effort runs:

```
tokens  ≈  154,000  +  1.05 × map_bytes
```

**A fixed cost of about 154,000 tokens, and roughly one token per byte of map.** That fixed cost
is **92% of Darwin's total** and still **62% of Prescott-Couch's**.

### Two things this is not

**It is not the reference documents.** The three documents the prompt says to read first, plus the
prompt and the skill, are 68,640 bytes — about **17,200 tokens, 11% of the fixed cost**. Cutting
them in half would save 6% of a run and cost the instructions that made these maps good.

**It is not the checker.** The whole check-and-fix loop, on the worst report measured here — old
Darwin with ten findings — is 3,279 bytes of JSON, under 900 tokens. Seven rounds of that is 6,000
tokens, **4% of one run**. The earlier finding stands and is now better evidenced: the checker was
never the cost.

### What the fixed cost is

The agentic loop itself. **Tool calls are 37 to 45 regardless of the paper** — 41 for a 266-word
passage, 44 for a 10,751-word judgment — because the *process* has a fixed number of steps: read
three documents, read the source, write, check, fix, check again. Every call re-sends the
conversation, so a run's cost is roughly the number of round trips multiplied by the context they
each carry. The paper is nearly free; the procedure is nearly all of it.

*(Tool calls correlate weakly with tokens only because their range is so narrow — 37 to 45. That
narrowness is the finding, not a weak relationship.)*

## Wall-clock time is not usable here, and saying why matters

| run | wall | ran |
|---|---|---|
| Miller | 20 min | alone |
| Tooming | 24 min | alone |
| Darwin | 40 min | four in parallel |
| Carroll | 43 min | four in parallel |
| Wilson | 51 min | four in parallel |
| Prescott-Couch | 58 min | four in parallel |

The two shortest papers took **twice as long** as the longest — and it means nothing about them.
Darwin, Carroll, Wilson and Prescott-Couch ran concurrently and contended; Miller and Tooming ran
alone. Read without the last column this table says short papers are slow, which is the opposite
of true. Tokens carry no such contamination, which is why every claim above rests on them.

## What would actually make this cheaper

### 1. Effort, which is the largest lever measured

The same paper, same instructions, differing only in effort:

| | tokens | wall | first-check faults |
|---|---|---|---|
| Tooming, `max` | 207,950 | 24 min | **0** |
| Tooming, `high` | 174,914 | 18 min | **8** |

**−16% tokens and −27% time**, for a map of comparable shape. The cost is visible in the last
column: `max` made no mechanical faults at all on its first pass; `high` made eight, seven of them
claims marked `quotation` whose own text was not the source's. The checker caught every one.

So the honest reading is that **`high` is a good default for a draft and a poor one for a shipped
sample** — not because its map was worse, but because more of its correctness came from the check
rather than from the writing, and the check cannot catch a misreading.

**Both arms are kept, side by side, in `effort-testing/`**, each a complete folder that opens in
Ipsissima, each frozen at the sha1 the ledger recorded. Its README carries a second comparison this
one does not: half of `max`'s claims are marked `quotation` against barely a quarter of `high`'s,
and `high` used `compression` nearly three times as often. That difference is recomputable from the
two files at any time, which the token figures above are not.

### 2. Fewer round trips, which is where the fixed cost lives

Two mechanisms observed in these runs, one wasteful and one not:

- **A truncated tool result costs a whole round trip.** Prescott-Couch made seven checker calls,
  two of them on the *same file state*, because "the first run's output was truncated, so I re-ran
  it to read the whole list". The full census on that map is 6,385 bytes; `--format json` on the
  same file is 88. The fix is not a shorter report — it is that **the fix loop should never call
  the prose census at all**, which the instructions already say and which a reconstructor reaching
  for a full picture will still do.
- **Pre-verifying spans locally saves rounds.** Darwin and Wilson both checked every `source:`
  span against `find_quote` directly before calling the checker. Wilson's caught a trailing full
  stop; Darwin's caught nothing but is why its first round had no quotation faults. Both reported
  it as saving a round, and a round is worth far more than the calls it costs.

### 3. Nothing, on the source side

This is the practical answer to the owner's question. **There is no lever on the reading.** A
266-word passage and a 10,751-word judgment cost within 27% of each other, so making the source
smaller, or the extraction of it cheaper, buys almost nothing. Effort in that direction is
misdirected, and this table is the reason to stop looking there.

---

## What this means for the project's purpose

The aim is that someone can map everything they read rather than a few papers for special study.
On these numbers **a reconstruction costs about the same whatever they are reading** — which is
good news for a reader of long papers and bad news for anyone hoping short ones would be cheap.

The floor is the fixed 154,000 tokens, and it is a floor set by the *procedure*, not by the text.
That is where anyone trying to make this affordable should look, and the two candidates the
evidence supports are **fewer round trips** and **effort chosen deliberately per job** — a draft at
`high`, a shipped sample at `max`.

# What the 154,000 tokens are actually spent on

*Added after the owner asked the obvious next question: 154,000 tokens of fixed cost is a great
deal, so what are the forty tool calls doing? This is read out of the five run transcripts —
209 calls — rather than inferred.*

## Every call, classified

| what the call was for | Darwin | Carroll | Prescott | Wilson | Miller |
|---|---|---|---|---|---|
| **run the checker** | 11 | 9 | 15 | 9 | 9 |
| **pre-verify quotations locally** | 11 | 13 | 5 | 4 | 5 |
| read the source | 4 | 5 | 3 | 9 | 14 |
| read the instructions | 3 | 3 | 3 | 3 | 3 |
| search / grep | 2 | 0 | 4 | 6 | 2 |
| read something else | 2 | 3 | 7 | 6 | 4 |
| run something else | 0 | 0 | 6 | 0 | 3 |
| look around the folder | 2 | 2 | 0 | 0 | 2 |
| **write the map** | 1 | 1 | 1 | 1 | 1 |
| edit the map | 3 | 1 | 0 | 2 | 0 |

**The map is written in a single call every time.** Ninety thousand bytes of Argdown, one `Write`.
Whatever is expensive here, it is not the writing.

**Verification is half of everything.** Checker runs plus local pre-verification are 22 of
Darwin's 41 calls and 22 of Carroll's 37. On a 266-word passage, twenty-two calls went on checking.

## The clearest waste: the checker is run on files that have not changed

The ledger records a content hash per run, so calls and *distinct file states* can be compared
directly:

| | checker calls | distinct states | redundant |
|---|---|---|---|
| Darwin | 11 | 3 | **8** |
| Carroll | 9 | 3 | **6** |
| Prescott-Couch | 15 | 5 | **10** |
| Miller | 9 | 3 | **6** |

**Between two and three times as many invocations as versions.** Prescott-Couch's report explains
one instance in its own words — the first run's output was truncated, so it re-ran the same file
to read the rest of the list — and the pattern elsewhere is the same shape: read the JSON to get
the faults, then run it again *unchanged* to read the prose census for the apex and the tag
counts, because the two are different outputs of the same command.

That is **six to ten round trips a run, 15–25% of all calls**, spent asking a question already
answered.

Three fixes, in order of how much they buy:

1. **Give the JSON everything the census has.** The reason a reconstructor runs the command twice
   is that `--format json` reports faults and the prose reports the shape — apex, tags,
   contribution, fidelity census. Those are facts about the finished map that a fix loop plainly
   wants; they cost nothing to serialise and would remove the second call outright. The earlier
   work already moved five prose-only *findings* into the JSON for exactly this reason. The census
   is the rest of the same problem.
2. **Say in the prompt that the census is never needed twice.** The instructions say to use
   `--format json`; they do not say that re-running for the prose is a wasted round trip, and a
   reconstructor reaching for a full picture will do it.
3. **Do not truncate the checker's output.** A truncated result costs a whole round trip, and the
   full census is only 6,385 bytes on the largest map in the corpus.

## The second-clearest: reading in pieces

**The instructions are read in exactly three calls in every single run** — one per document,
68,640 bytes total. One `cat` of all three would be one call. That is two calls a run, free.

**The source is read in 3 to 14 calls.** Miller's fourteen are a long judgment read in sections,
which is reasonable; Wilson's nine on a paper of similar length are less obviously so. A first
pass that reads the whole source once, then re-reads only what it needs, would cut most of this.

## The one to think hardest about: local pre-verification

Darwin made **eleven** local `find_quote` calls, Carroll **thirteen**, checking each `source:` span
before ever calling the checker. Both reported it as a saving, and in one sense it is: Wilson's
caught a trailing full stop, Darwin's is why its first check had no quotation faults.

But **a local call is a round trip too**, and the arithmetic is not obviously favourable. Darwin
spent eleven calls to avoid perhaps one checker round. If the goal is fewer round trips, verifying
twelve spans in one script rather than eleven scripts is the same information for a tenth of the
cost — and that is a matter of instruction, not tooling.

## What this could plausibly save

Nothing here touches the reading, the judgement, or the map. On these five runs:

| | calls saved |
|---|---|
| stop re-running the checker on unchanged files | 6–10 |
| read the three instruction documents in one call | 2 |
| batch local span verification | 3–12 |
| read the source in fewer passes | 0–8 |

**Roughly 11 to 32 of about 40 calls**, without changing a single thing about how the argument is
reconstructed. The fixed cost is a procedure, and the procedure has slack in it.

**What it will not save.** The three documents still have to be read — 17,200 tokens, and the maps
got better when they started being read. The map still has to be written. The check still has to
run once per revision. A floor remains; it is just lower than 154,000.

## The honest caveat

Round trips and tokens are not the same quantity, and this file does not have the data to convert
one into the other. Tokens correlate with tool calls at only **r = +0.505** across these runs —
weakly, because the range is so narrow — while they correlate with map size at **+0.989**. So the
saving above is stated in **calls**, which is what was measured, and not in tokens, which was not.
What licenses the inference is the structural fact that each call re-sends the conversation: the
cost of a run is the number of round trips multiplied by what each one carries. Halving the calls
should move the fixed cost substantially. **It is a prediction, and the ledger is already in place
to test it on the next reconstruction.**

## Method, and its limits

Six runs at one effort level is not many, and none of this is controlled for paper difficulty:
Prescott-Couch is a critical notice with 58 reported claims and cost the most, which may be about
the genre rather than the map size. The one properly controlled comparison here is the Tooming
pair, because it is the same paper twice.

Every number is from the agents' own reported usage and from `~/.ipsissima/check-log.jsonl`,
which has recorded every check since this morning. `eval/check_patterns.py` reads it: **10 of 14
files were clean on the first check**, and of the faults that did appear on a first pass, 19 of 29
were missing warrants.
